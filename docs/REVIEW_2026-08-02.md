# Chamber code review — 2026-08-02

Review of the tree as exported (`chamber-export.zip`, baseline commit `a49f4c5`).
Every finding below was **proven by running code**, not by reading it. Probes are
in `probes/` and are runnable.

**Verdict:** strong architecture and unusual discipline in places; the
security-critical enforcement layer does not match the documentation. Good
week-1/2 skeleton, not ready to carry real work.

State at review: ~16k LOC TypeScript, **zero runtime dependencies**
(`node:sqlite` + `node:crypto`), 99/99 tests green in ~2.5s.

---

## What is genuinely good

- **Zero dependencies.** No `node_modules`, no lockfile, no supply chain. For a
  governance kernel this is the right call and rare discipline. Preserve it.
- **The SQL schema does real work.** Two malformed probe inputs were caught by
  `CHECK` constraints, not by JS. Defence at the storage layer.
- **Approval idempotency is actually tested** — double-approve, approve-after-reject,
  apply-while-pending. Most projects skip these.
- **Hash-chained audit + incremental MMR + exportable checkpoint receipt**
  (`src/checkpoint_export.ts`) is a sophisticated, correct design.
- **Docker deploy is sane:** non-root, no published ports, `CHAMBER_API_TOKEN:?`
  required, loopback default bind.
- **The schema is consistently better than the code.** Several "gaps" are
  unimplemented intent rather than bad design — `span_hash`, `context_hash`,
  `pays_subclaim`, and the `proposed_paid` debt state all exist and are unused.
  That makes them cheaper to close than the severity below suggests.

## Findings

### 1. The sandbox does not isolate, and `CHAMBER_SANDBOX_REQUIRED=1` is a no-op

**Severity: critical.** This is the path `synthesizeTool()` runs model-generated
code through.

`detectSandboxBackend()` (`src/sandbox.ts:60`) can never return `"none"` — it
falls back to `"subprocess"`. So the fail-closed branch at `src/sandbox.ts:204`
is unreachable. Probed with `CHAMBER_SANDBOX_REQUIRED=1` set:

```
REQUIRED env = 1
detectSandboxBackend() = docker      ← docker is never actually invoked
backend reported: subprocess  ok: true
{ "home": "/Users/<user>", "homeReadable": true,
  "sshExists": true, "secretsExists": true,
  "wroteOutside": true, "net": "RESOLVED 172.66.147.243" }
```

It ran anyway, read `$HOME`, saw `~/.ssh` and `~/.secrets`, **wrote a file to
`$HOME`**, and resolved DNS. `bwrap` is Linux-only, so on macOS this always
degrades to a bare child process with a scrubbed env. `src/sandbox.ts:232`
relabels a docker-detected run as `"subprocess"` — the "docker path not fully
wired" comment is accurate but the detection still advertises it.

Reproduce: `probes/sandbox_escape.ts`

### 2. The two flagship gates are not in the audit chain

**Severity: high.** `commit_belief.ts` and `try_activate_skill.ts` write only to
`gate_event` — a plain, unchained table. Sixteen other modules call
`appendAudit`. The README's central invariant is about precisely these two.

Measured on a live run: **4 `gate_event` rows, 0 `audit_event` rows.**

Reproduce: `probes/gate_audit.ts`

### 3. The citation gate is `sources.length > 0`

**Severity: high.** Nothing verifies that a pin resolves or that its hash matches
any content. `src/commit_belief.ts:107` checks only that `snapshotHash` is
truthy; the debt-mint condition at `src/commit_belief.ts:241` is
`sources.length === 0`.

```
commitBelief({ type: "belief", stakes: "consequential",
  text: "Aspirin cures stage IV pancreatic cancer in 100% of patients.",
  sources: [{ kind:"url", refId:"https://example.invalid/does-not-exist",
              snapshotHash: "aaaa" }] })
→ { ok: true, beliefId: "blf_a4a9…" }   debts minted: 0   status: active
```

`src/commit_belief.ts:240` calls this a "v1 heuristic" — the code is honest, the
README is not.

Reproduce: `probes/pin_bypass.ts`

### 4. Secrets fail open

**Severity: high.** `sealSecret` (`src/secret_box.ts:34`) stores `plain:` +
plaintext unless **both** `NODE_ENV=production` and `CHAMBER_REQUIRE_TOKEN_KEY=1`.
The shipped `deploy/Dockerfile` sets the first and not the second — so the
production image stores OAuth tokens in plaintext by default. A passphrase key
also goes through bare `sha256` with no KDF or salt.

### 5. Nothing type-checks this

**Severity: medium.** No `tsconfig.json`, no linter, no CI.
`--experimental-strip-types` *strips* types without checking them.

Under `tsc --strict`: **91 errors.** Measured breakdown:

| Count | Code | What |
|-------|------|------|
| 38 | TS2554 | All in `tests/harness.ts` — `assert(x)` vs a 2-arg signature. **One line clears 38.** |
| 25 | TS7031/TS7006 | Implicit `any`, mostly discord.js callbacks |
| 13 | TS2352 | `.all() as Row[]` array casts |
| 5 | TS2339 | Real — includes `CommitResult` union misuse at `src/contract.ts:109,181` |
| 4 | TS2307 | `discord.js` not declared as a dependency |
| 4+2 | TS2345/TS2300 | Arg mismatch; duplicate `listPendingQueue` at `src/cli.ts:26,95` |

Only ~11 are genuine logic-level defects.

### 6. Green tests, happy paths only

**Severity: medium.** No test asserts the sandbox *isolates* anything — only that
code runs and output is captured (`tests/harness.ts:992`, `T1_sandbox_self_test`).

Zero coverage on: `gateway.ts`, `gateway_runner.ts`, `slack_runner.ts`,
`discord_runner.ts`, `mcp_client.ts`, `skills_registry.ts`, `pilot.ts`,
`plugins/telegram.ts` — i.e. **every network-facing surface**.

## Smaller, still worth fixing

- **`src/db.ts:49`** — on disk I/O error the audit DB silently falls back to
  `/tmp/chamber.sqlite`, then `:memory:`. A tamper-evident ledger that silently
  becomes amnesiac is worse than one that fails to open.
- **`src/audit.ts:71`** — `chainEnabled()` is called and its result discarded.
  The `audit.chain_enabled` config key does nothing.
- **`src/audit.ts:100`** — transaction detection is exception-driven
  (`try { BEGIN IMMEDIATE } catch { assume already in TX }`). A `SQLITE_BUSY`
  is misread as "already in a transaction" and the append runs in autocommit,
  breaking the one-transaction invariant the project is built on.
- **Audit chain is unkeyed** (plain sha256, no HMAC) and lives in the same SQLite
  file it protects. Anyone with DB write access can rewrite it and recompute
  every hash. It is corruption-evident, not tamper-evident, until a checkpoint is
  externally anchored or signed.
- **105 unchecked `as { … }` casts** on SQL rows; e.g. `src/audit.ts:108` throws
  on a missing tip row rather than failing cleanly.
- **`src/server.ts:64`** — hand-rolled `tokenOk` instead of
  `crypto.timingSafeEqual`. The comment ("constant-time-ish") is honest; the
  length-mismatch branch leaks length only. Low risk, easy fix.
